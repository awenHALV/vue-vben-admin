# 国际化配置文件生成指南

本文档用于快速生成新模块的国际化配置文件。

## ⚠️ 重要：键名命名规则

**国际化文件的键名由文件名决定！**

项目中的国际化文件按文件名分组：

```
locales/langs/zh-CN/
├── system.json    → 使用 $t('system.xxx')
├── page.json      → 使用 $t('page.xxx')
├── app.json       → 使用 $t('app.xxx')
└── demos.json     → 使用 $t('demos.xxx')
```

**示例：**
- `system.json` 中的 `powerPlant.title` → 使用时是 `$t('system.powerPlant.title')`
- `page.json` 中的 `powerPlant.title` → 使用时是 `$t('page.powerPlant.title')`

## 快速开始

### 当创建新模块时，按以下步骤配置国际化：

#### 步骤 1：确定模块分类

- **系统管理模块** → 使用 `system.json` → 调用时使用 `$t('system.xxx')`
- **业务页面模块** → 使用 `page.json` → 调用时使用 `$t('page.xxx')`
- **示例/演示模块** → 使用 `demos.json` → 调用时使用 `$t('demos.xxx')`

#### 步骤 2：编辑中文语言包

编辑文件：`apps/web-antdv-next/src/locales/langs/zh-CN/{目标文件}.json`

#### 步骤 3：编辑英文语言包

编辑文件：`apps/web-antdv-next/src/locales/langs/en-US/{目标文件}.json`

## 自动化脚本（可选）

如需批量生成国际化文件，可创建脚本：

```bash
# scripts/generate-i18n.js
const fs = require('fs');
const path = require('path');

const moduleName = process.argv[2];
const moduleTitle = process.argv[3];

if (!moduleName || !moduleTitle) {
  console.error('Usage: node scripts/generate-i18n.js <moduleName> <moduleTitle>');
  process.exit(1);
}

const zhCN = {
  [moduleName]: {
    title: moduleTitle,
    list: `${moduleTitle}列表`,
    add: `新增${moduleTitle}`,
    edit: `编辑${moduleTitle}`,
    delete: `删除${moduleTitle}`,
    // ... 更多配置
  }
};

const enUS = {
  [moduleName]: {
    title: moduleTitle,
    list: `${moduleTitle} List`,
    add: `Add ${moduleTitle}`,
    edit: `Edit ${moduleTitle}`,
    delete: `Delete ${moduleTitle}`,
    // ... 更多配置
  }
};

// 写入文件
fs.writeFileSync(
  path.join(__dirname, '../apps/web-antdv-next/src/locales/langs/zh-CN/page.json'),
  JSON.stringify(zhCN, null, 2)
);

console.log(`国际化配置已生成：${moduleName}`);
```

使用：

```bash
node scripts/generate-i18n.js powerPlant "虚拟电厂档案"
```

## 常见问题

### Q: 应该使用 system.json 还是 page.json？

**A:** 
- 如果模块属于系统管理功能（用户、角色、权限等）→ `system.json`
- 如果模块是独立业务页面（虚拟电厂、订单管理等）→ `page.json`
- 如果模块是示例/演示代码 → `demos.json`

### Q: 已有通用键名是否需要重复配置？

**A:** 
不需要。如果 `common.add` 已存在，直接使用 `$t('common.add')` 即可，无需在模块中重复配置。

### Q: 如何验证国际化配置是否正确？

**A:** 
1. 在浏览器中切换语言（设置 → 语言）
2. 检查页面文本是否正确切换
3. 查看浏览器控制台是否有缺失的 key 警告
